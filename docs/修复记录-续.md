# 修复记录（续）— HistoryScreen / SettingsScreen / baseUrl 多环境

> 延续 `docs/修复记录.md`。本批聚焦 Android 端最后两个"待实现"屏幕，以及后端地址的多环境配置。

## 1. HistoryScreen（历史天气）— 已接真实数据
- 新增模型 `WeatherHistory`（`data/model/Models.kt`）：字段 `city_id / date / temp_max / temp_min / precipitation / wind_speed_max / data_source`，与后端 `/api/weather/historical/{cityId}` 返回结构一致。
- `ApiService` 新增 `getHistorical(cityId, latitude, longitude, start_date, end_date): List<WeatherHistory>`；`WeatherRepository.getHistorical(...)` 封装调用。
- 屏幕逻辑：进入即拉取关注城市 → 默认选中第一个 → 自动加载"近 7 天"历史；提供**城市下拉**与**近7/30/90天**时间范围切换；展示每日最高/最低温、降水、最大风速卡片；含加载/错误/空态。
- 数据来源：Open-Meteo `archive` 接口（免费，按经纬度回放历史），与实时/预报同源，避免 CMA 死代码路径。
- 说明：未使用 `/api/history/query`（该接口按 `station_id` 查本地观测库，而关注城市多无 `station_id`，且 `HistoryObservation` 表当前未写入）。

## 2. SettingsScreen（设置）— 已接真实功能
- 新增 `SettingsManager`（DataStore `settings`）持久化"预警推送通知"开关。
- 退出登录：`WeatherRepository.logout()` → 调 `POST /api/auth/logout` 并清 Token（DataStore）→ 导航回登录页并清空返回栈。
- 清除本地缓存：`WeatherRepository.clearCache()` → `CachedWeatherDao.clearAll()`，带二次确认弹窗。
- 关于区：展示数据来源（Open-Meteo）与版本号（0.1.0）。
- 预警推送开关目前为**偏好持久化**（README 承诺的推送能力未实现，本开关为其前置配置项，后续接 WorkManager + 通知渠道即可生效）。

## 3. RetrofitClient baseUrl → buildConfigField（多环境）
- `RetrofitClient` 改为 `private val BASE_URL = BuildConfig.BASE_URL`，去掉硬编码 `const`。
- `build.gradle.kts`：`defaultConfig` 注入 debug 默认 `http://10.0.2.2:60245/`（模拟器访问宿主机）；`release` 覆盖为生产域名 `https://api.maozi-weather.com/`；并显式开启 `buildFeatures { buildConfig = true }`。
- 真机调试：把 debug 的 `BASE_URL` 改为电脑局域网 IP（如 `http://192.168.x.x:60245/`）即可。

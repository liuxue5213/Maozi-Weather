# 毛仔天气 · 修复与优化记录

> 基于《项目分析报告》发现的问题，本次对后端、Web 管理端、Android 端进行了修复与功能落地。
> 时间：2026-08-26

## 一、后端

### 1. AQI 国标换算（严重：数值与颜色含义错位）
- 文件：`backend/app/utils/open_meteo_client.py`、`backend/app/routers/public.py`、`backend/app/services/air_quality_service.py`
- 问题：原代码把 Open-Meteo 的 `european_aqi`（欧标刻度 0-20 优 / 20-40 良 …）直接当 `aqi` 返回并套用"优/良/轻度污染…"中文等级，与前端按国标阈值（≤50 绿 / ≤100 橙 …）上色完全不一致。
- 修复：改用项目已有的 `calculate_aqi`（GB 3095-2012），用实际污染物浓度换算国标 AQI；其中 CO 单位为 µg/m³，换算国标时需 ÷1000（国标 CO 限值为 mg/m³）。新增 `aqi_primary` 首要污染物字段。
- 影响：`/api/weather/air_quality`、`/api/public/weather` 的 AQI 现均为国标值，与 Web/Android 颜色阈值一致。

### 2. CORS 白名单（严重：生产环境 Web 连不上后端）
- 文件：`backend/app/core/config.py`、`backend/app/main.py`
- 问题：`allow_origins=["*"] if APP_DEBUG else []`，生产（APP_DEBUG=False）时 origins 为空列表，Web 端跨域请求全部失败。
- 修复：新增配置 `CORS_ORIGINS`（逗号分隔来源）；留空时开发环境放行全部来源，生产环境必须显式配置；通配来源时自动关闭 `allow_credentials`（Starlette 不允许通配 + credentials 并存）。

### 3. 调度器真正预热缓存（功能：原为空壳）
- 文件：`backend/app/services/scheduler.py`
- 问题：`refresh_realtime/forecast/warning_cache` 全是 `pass` + TODO，所谓"定时拉取关注城市"从未执行。
- 修复：从 `user_cities` 关联 `cities` 取去重后的关注城市坐标，逐个调用 `multi_source_weather` 预热 Redis 缓存；用 `asyncio.Lock` 防止长任务被重复触发；未配置 QWeather（`QWEATHER_API_HOST`）时跳过预警拉取。

### 4. 历史同步并发与重试（功能/健壮性）
- 文件：`backend/app/services/scheduler.py`、`backend/app/services/history_sync.py`
- 问题：选中 `pending/failed` 任务后未先置 `running` 就 `create_task`，长任务（>1 分钟）会被重复选中；`failed` 任务无退避无限高频重试；`execute_sync_task` 又要求状态为 pending/failed，刚被置 running 的任务会被误判跳过。
- 修复：`process_history_tasks` 先置 `running` 再异步执行；`execute_sync_task` 改为仅排除 `completed`；`failed` 任务加入 5 分钟退避（按 `updated_at` 过滤）。

### 5. 公开路由缓存 + 限流（安全/性能）
- 文件：`backend/app/routers/public.py`
- 问题：`/weather`、`/search/city` 公开无缓存、无限流，易被刷且每次穿透到上游。
- 修复：进程内 10 分钟 TTL 缓存（单实例足够；多实例建议改 Redis）+ 每 IP 限流（天气 120/min、搜索 60/min），超限返回 429。

## 二、Web 管理端

### 6. 数据来源标识（误导）
- 文件：`web-admin/src/views/Weather.vue`
- 问题：底部写死"数据来源：中国气象局"，与真实来源（Open-Meteo / 和风天气增强）不符。
- 修复：改为动态显示真实 `data_source`（缺省回退"Open-Meteo（和风天气增强）"）。

## 三、Android 端

### 7. ApiService 契约修复（严重：一接真实接口就 422）
- 文件：`android-app/.../data/api/ApiService.kt`、`android-app/.../data/model/Models.kt`
- 问题：`getRealtime/getForecast/getAirQuality` 未传 `latitude/longitude`，而后端这两个参数是必填；`getForecast` 声明返回 `List<WeatherForecast>`，但后端返回 `{daily, hourly, sun}` 结构，反序列化会失败。
- 修复：补齐 `latitude/longitude` 查询参数；新增 `WeatherForecastResponse`（daily/hourly/sun）包装类对齐后端结构。

### 8. 统一数据仓库
- 文件：新增 `android-app/.../data/repository/WeatherRepository.kt`
- 封装网络请求 + Room 离线缓存 + DataStore Token，在 `WeatherApplication.onCreate` 初始化。

### 9. 核心页面接入真实数据
- `LoginScreen`：真正调用登录接口并存 Token（原直接放行）。
- `HomeScreen`：拉取关注城市 + 各城实况，网络异常回退 Room 缓存；卡片点击进入详情并缓存选中城市坐标。
- `WeatherDetailScreen`：展示真实实况 / 空气质量（按国标 AQI 着色）/ 未来预报 / 生活指数 / 日出日落。
- `CityManageScreen`：搜索城市、添加关注、删除关注（原"待实现"）。

### 10. 日志降级（安全）
- 文件：`android-app/.../data/api/RetrofitClient.kt`
- 问题：`HttpLoggingInterceptor.Level.BODY` 会明文打印含 Token 的响应体。
- 修复：Debug 包 BODY，Release 包降级为 BASIC。

## 四、验证
- 后端相关 Python 文件已通过 `ast` 语法检查。
- 端点对齐确认：Android 调用的 `/api/auth/login`、`/api/cities/list`、城市 `search/add/delete`、`/api/weather/{realtime,forecast,air_quality,life_index,sun}` 与后端路由、参数、返回结构一致；`UserCityOut` 已嵌套 `city`（含 latitude/longitude）。

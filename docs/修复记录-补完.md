## 1. 后端 public 路由：缓存/限流迁移到 Redis

**文件**：`backend/app/routers/public.py`

原实现用进程内 dict（`_WEATHER_CACHE` / `_SEARCH_CACHE` / `_RATE`）做缓存与限流，在 Gunicorn/多 worker、多实例部署下会失效（各进程各算各的，且限流可被绕过）。

改为基于 `app/core/redis.py` 的 async Redis 客户端：

- `GET /weather`、`GET /search/city` 的响应缓存写入 Redis，key 为 `weather:{lat}:{lon}` / `city:{name}`，TTL 10 分钟（`json.dumps(ensure_ascii=False)`）。
- 限流改为按 IP + 分钟分桶的 Redis 固定窗口：`ratelimit:{ip}:{bucket}` 用 `INCR` + `EXPIRE`，`/weather` 120 次/分钟、`/search/city` 60 次/分钟，超限返回 429。
- **降级策略**：Redis 不可用时缓存与限流均静默跳过（`except` 兜底），接口仍可正常对外服务，不会因 Redis 抖动而 5xx。
- 同步辅助函数改为 `async`，调用处加 `await`，缓存 key 显式加前缀以区分业务。

依赖：`redis.asyncio`（已在 `app/core/redis.py` 使用；需 `redis` 服务可达，地址来自 `settings.redis_url`）。

## 2. Android 后台刷新 + 预警通知（WorkManager）

**新增**：`android-app/.../worker/WeatherRefreshWorker.kt`
**改动**：`WeatherApplication.kt`（注册周期任务）、`WeatherRepository.kt`（新增 `getWarning`）、`build.gradle.kts`（WorkManager 依赖已存在）

- `WeatherApplication.onCreate` 中通过 `WorkManager.enqueueUniquePeriodicWork` 注册每 **15 分钟**执行一次的周期任务（`weather_refresh`，`ExistingPeriodicWorkPolicy.UPDATE`，初始延迟 1 分钟）。
- `WeatherRefreshWorker`（CoroutineWorker）：
  1. 未登录（`TokenManager.isLoggedIn`）直接 `Result.success()` 跳过，避免无意义重试。
  2. 拉取关注城市实况 → 写 Room 缓存（`CachedWeather`，与首页/小组件同源同主键 `cityId`）。
  3. 若 `SettingsManager` 预警推送开关开启，对 `getWarning` 返回中 `effective == 1` 的预警逐条发通知（复用 `WeatherApplication.WARNING_CHANNEL_ID` 通知渠道，小图标 `ic_dialog_alert`）。
  4. 刷新结束后调用 `WeatherWidget().updateAll(context)` 同步桌面小组件。
  5. 异常时 `Result.retry()`，由 WorkManager 按退避策略重试。
- 鉴权链路由 `RetrofitClient` 的 OkHttp 拦截器自动携带 DataStore 中的 JWT；WorkManager 运行于应用进程，Token 可用。

注意：Android 12+ 需 `POST_NOTIFICATIONS` 权限（清单已声明），运行时权限申请建议在前端"设置"页引导（本篇未加运行时弹窗，属后续可选项）。

## 3. Android 桌面小组件（Glance）

**新增**：
- `android-app/.../ui/widget/WeatherWidget.kt`（`WeatherWidget` + `WeatherWidgetReceiver`）
- `android-app/.../res/xml/weather_widget_info.xml`（AppWidget 元数据，30 分钟系统刷新）
- `android-app/.../res/layout/weather_widget_loading.xml`（初始占位布局，避免引用库内资源报错）
**改动**：`AndroidManifest.xml`（已含 receiver 声明，指向 `.ui.widget.WeatherWidgetReceiver`）、`build.gradle.kts`（新增 `androidx.glance:glance-appwidget:1.0.0`）、`WeatherDatabase.kt`（`.enableMultiInstanceInvalidation()`，便于多进程访问）

- 小组件读取 Room 本地缓存（`WeatherRepository.getCachedCities()`），展示前 3 个关注城市的名称/温度/天气；无缓存时提示"打开 App 添加关注城市"。
- 数据加载在 `provideGlance`（suspend）内完成，再用 `provideContent` 渲染，避免 composable 内阻塞。
- 背景蓝 `#1B5E9B`、文字白色（`ColorProvider`），通过 `androidx.glance.background` + `androidx.glance.color.ColorProvider` 设置。
- 刷新来源：系统每 30 分钟 + WorkManager 每 15 分钟（worker 调 `updateAll`）+ 下次 App 打开触发后台任务时。
